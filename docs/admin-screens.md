# Admin screens

The portal is a left **sidebar** + content area (`apps/admin/src/app/(app)/layout.tsx`). Nav lives in `apps/admin/src/components/sidebar.tsx`. Every screen is Spanish (copy from `src/i18n/es.ts`). Data goes through `@dmtx/api-client` + TanStack Query; forms use react-hook-form + Zod.

## Built

- **Login** (`/login`) — email/password via `@dmtx/auth/client`.
- **Ejercicios** (`/ejercicios`) — list with a status dropdown (Activos / Archivados / Todos) and a checkbox column. Selecting rows shows a bulk bar over the header: Agregar músculos, Agregar equipo (the same pickers as the form), Archivar / Restaurar, and "···" with Quitar músculos, Quitar equipo (tick which of the selection's tags to drop) and Eliminar (refused per exercise when a rutina, reusable block or user result uses it; the bar reports which stayed). `POST /api/exercises/bulk`. Create (`/nuevo`) and edit (`/[id]`) share `ExerciseForm` (name, description, multimedia, cues, aliases, difficulty, músculos, equipo). This is the **reference implementation** — copy its shape for the other entities.

## To build (roadmap order)

Each follows the same pattern: list (TanStack Table) + create/edit (RHF + Zod against `@dmtx/schemas`) + a resource on the API + a method on `@dmtx/api-client`.

- **Músculos** (`/musculos`) and **Equipos** (`/equipos`) — one flat list each, as a table: search, an add row at the top (Enter adds and keeps the focus for the next name), click a name to rename inline, and a checkbox column whose bulk bar (it covers the header row, like Shopify) deletes the selection after a confirm. Deleting a tag takes it off the exercises that carried it; the exercises stay. Each row shows how many exercises use it. The exercise form tags like Shopify's product tags: the field shows the chosen chips and an "⊕ Agregar" button opens a popover to search and tick existing ones; a name that doesn't exist is created from there ("Agregar «…»").
- **Rutinas** (`/rutinas`) — the big one. A rutina is three sections — Rutina, Calentamiento, Estiramiento — each a tab, and **each tab can have the written rutina, a video, or both** — with both, the app lets the user follow the class or be guided exercise by exercise. Each section is **guided** — its written rutina, every exercise with its own demo video — and may also have a **class video** the user can follow instead; the class is optional — with none, a quiet «+ Agregar rutina / calentamiento / estiramiento en video (opcional)» line above the editor (click opens the library, a drop uploads); with one, a slim bar in the same place (`MediaField` `variant="bar"`: thumbnail, name, length, size; click to change, eye to preview, trash can to remove, upload progress in place). Each tab shows the icons of what it holds — a list for a written rutina, a play frame for a class. The preview draws each exercise with its demo thumbnail (a dashed gap when it has none, so missing demos show), and shows a class video as the video itself — Stream's poster frame at 16:9 with a play button and the length, «Procesando…» while Stream encodes, «El video ya no está en la biblioteca» if the file is gone — and, with a written rutina too, «o guiada, ejercicio por ejercicio» and its exercises under it. The header reads e.g. «Video o AMRAP · 9 min» (a section's video length counts, not its text estimate). The list shows a «Contenido» column with the same icons. Publishing needs the main section to have a written rutina, a video, or both. Skill levels are always written (no video half). The text tabs share a full-height **text editor** styled like VS Code (dark theme, tab bar, line numbers, gutter error markers, token colours, a "Problemas" panel underneath; `rutina-text-editor.tsx`) where the whole rutina is written in the [rutina text notation](rutina-text.md) — format on the first line, `N rondas:` groups, `41 burpees  kg tempo 0-3-1-1` items, `Calentamiento:`/`Estiramiento:` sections — with autocomplete while typing (exercises by name/alias, typo-tolerant suggestions, units, modifiers; only an exactly written name resolves) and a "+" menu (gutter, or a click/Enter on a blank line) for structure: formats, rondas, descansos, plantillas, reusable blocks and other rutinas, inserted with ⟨placeholders⟩ that Tab walks through, inline diagnostics shown as a Grammarly-style card on hover or when the word is selected (suggestions apply on click; unknown exercise → "Crear ejercicio"), recognised exercise names read as links (dotted underline on hover) and a click opens the full exercise form in a dialog (the archived-exercise card has the same action; renaming rewrites the name in every section and version of the open rutina and keeps the old name as an alias), the athlete-facing preview always visible in the right column (it follows the active variant tab), a **first-run tutorial** (`ui/tour.tsx`, coach marks: the page dims except the step's element and a card explains it; the page stays usable, a step that asks for something moves on by itself once it is done, and it steps aside while a modal is open): the first time an admin opens the rutina or program editor (once per browser, `localStorage` `dmtx.tour.rutina-editor.v1`; the Guía's «Ver el tutorial» replays it) it walks through writing a short rutina («Escríbelo por mí» types one with a catalog exercise), the preview (a guided rutina: each exercise shows its own demo video), the section tabs, the optional class video (pick or upload one) and the Guía; and a searchable guide in a drawer behind the "Guía" button (`rutina-guide.tsx`, with «Guiada o clase en video» explaining the two modes): live examples (a real editor with a demo catalog, plus the athlete's preview) and CSS-animated scenes for the mouse-driven parts (the + menu, the error card, click-to-edit an exercise, the placeholders), so it never goes stale. A tab bar holds the **variants** (RX / Escalada / …): "+" copies the active tab into a new variant, double-click renames, ✕ removes; every tab is validated and saved with the base. Undo/redo buttons sit on the right (⌘Z / ⇧⌘Z, Ctrl+Z / Ctrl+Y). Select two or more lines → "Guardar como bloque" saves them as a reusable block; saved blocks and other rutinas are suggested by name and inserted whole. Publishing refuses a tab set to video without a file.
- **Bloques reutilizables** (`/bloques`) — reusable rutina text blocks (`reusable_blocks`): rename, edit text, delete. Created from the rutina editor.
- **Programas** (`/programas`) — a table (thumb, name, weeks, difficulty, status, updated) and the rutina editor in program mode: one bar above the editor holds a "Semana N" dropdown (switch week, duplicate one — the copy goes right after it — remove one, add an empty one) and the seven days of that week as cells (click to edit a day, drag to move it within the week; a dot = has content, hatched = rest day). The same bar says what the day is: structured text, a single video (like a rutina) or "Descanso". Catalog rutinas are reused through the + menu (their text is copied). Publishing refuses a day with nothing in it. Each day's rutina is saved as a workout owned by the program (not listed anywhere else).
- **Habilidades** (`/habilidades`) — the rutina editor in skill mode: the "Nivel ▾" dropdown lists the levels (add, rename, reorder with ↑↓, remove; the new one copies the active level), each level has the Rutina / Calentamiento / Estiramiento tabs plus **Objetivo**: not an editor but a panel (`skill-goals.tsx`) listing the exercises the level's Rutina uses, each with a tick box and, once ticked, the mark to reach («al menos [15] repeticiones / segundos / metros / kg × [5] rep.», suggested from how the rutina prescribes it; the unit can only be one the rutina measures the exercise by — reps for «10 sentadillas», reps or kg for «10 sentadillas @45 lb», seconds for «30s plancha», metres for «400 m» — and a goal whose unit the rutina no longer measures is flagged and refused on save); all ticked goals must be met in one session of the level's rutina to unlock the next level. A goal about an exercise no longer in the rutina shows struck through («Ya no está en la rutina de este nivel», «Quitar») and saving refuses it. The goals are kept in the level's text as its "Objetivo" section (written with `goalLine`, read back with `goalsFrom`), so the API and the app are unchanged. The preview ends with "Objetivo · para pasar al siguiente nivel". Saving refuses a level without goals unless it is the last (there it is optional: «Meta final de la habilidad»). Each level's rutina is saved as a workout owned by the skill (not listed anywhere else).
- **Colecciones** (`/colecciones`) — Netflix rows; add mixed items (workout/program/skill) with ordering.
- **Biblioteca** (`/biblioteca`) — the media library on Cloudflare Images (images) and Stream (videos), listed Shopify-style as a table (thumbnail + name + type, alt text, date, size, **Usos** — a dropdown with every exercise/rutina/program/skill/level/collection that references the file, linked — and **Reemplazar**: upload another file of the same kind and it takes the asset's place, same id, so every reference shows the new one; `POST /api/media/:id/replace` moves the finished upload's file into the row and deletes the old file). **Folders** (`media_folders`, nested): «Nueva carpeta» in the header, folder rows at the top of the list (open on click; Renombrar / Eliminar — deleting moves what it holds up to the parent), the open folder in the URL (`?carpeta=`) with a breadcrumb in the header, uploads filed under the open folder, a search spanning every folder, and «Mover a…» in the bulk bar (searchable folder list, root included, with «Nueva carpeta» inline; `POST /api/media/move`). The **media field** (every image or video slot in the portal, `media-field.tsx`) works like Shopify's: clicking it opens the library picker with the current file already marked (the picker uploads too), dropping a file on it uploads straight away, and on hover an eye opens «Vista previa» (the image big, or the video playing, with its details) and a trash can takes the file off; a video shows its poster frame with a play badge, and a file no longer in the library shows «El video ya no está en la biblioteca» (click to pick another, or the trash can). The picker dialog keeps the tile grid with its drop zone, and each tile has an eye on hover that opens a «Vista previa» pane beside the grid (`media-preview.tsx`) with ← → through the files — the drop zone sits above the tiles, so with the preview open it narrows with them and the preview gets the full height (Shopify); a drop anywhere in the picker uploads, and the zone lights up while dragging; the table has none: «Subir» sits in the toolbar and dropping files anywhere on the list uploads them (an overlay says so while dragging). Uploads run in the background through a global queue (`lib/uploads.ts`, the tray bottom-right). A dropped file shows up at once, as a placeholder row (or tile) saying «Preparando…» and in the tray, while its name is checked, a big image re-encoded and its record created; the placeholder stays until the list has the real row. The media record is created as `uploading` the moment the file is dropped and the field or tile gets its id right away, so the admin can save, change day or move around the portal while the bytes go straight to Cloudflare (`api.media.upload` with `onStarted`/`onProgress`: one multipart POST for an image, resumable tus chunks for a video). An image over 10 MB (Images' limit) is re-encoded as a JPEG in the browser first (`lib/prepare-image.ts`), same pixels, a tenth of the bytes. After the bytes are in, a video shows «Cloudflare está procesando el video…» until Stream has encoded it (a few minutes; the field, the thumbs and the list poll meanwhile) and then plays in the field through Stream's player; its duration comes from Stream. The tray lists the queue (scrolls when long) with «Cancelar» per file and «Cancelar todo»; the field has its own «Cancelar» while its file goes. Cancelling, also while Stream is still encoding, stops the transfer and deletes the record and the file at Cloudflare (`POST /api/media/:id/abort`), and the field lets go of the id. Reloading or closing the tab is the only thing that loses an upload (the browser asks first); a record left `uploading` with nothing in flight shows as interrupted and is removed by the admin. Failed uploads delete their record (references set null); a video Stream could not encode stays as `failed` until replaced. Clicking a tile opens the file at `/biblioteca/[id]`, the way Shopify opens a file: the image (or Stream's player) big on the left and, on the right, its name and alt text (editable, `PATCH /api/media/:id`), the details (type, dimensions, size, duration, date) and, in a section of its own with the count beside its title, **Usado en** (`GET /api/media/:id/usage`: the exercises, rutinas, programs, skills, levels and collections that reference it, one linked row each with a video or cover icon, the name and «Rutina · como video»), plus Eliminar — refused while any content uses it (the API answers 409 with the list; the dialog shows where to unlink it first); the bulk delete of the list does the same per file, deleting only the unused ones. An image is also **edited in place** there, with Shopify's three tools and no more (`components/image-editor.tsx`, a canvas fed by `GET /api/media/:id/original`, the full-size file proxied through the API so the pixels can be read back): **Información** (name, alt text), **Usado en**, **Recortar y transformar** (a crop box with handles and the presets Original / Cuadrado / 3:2 / 5:4 / 7:5 / 16:9 / Libre, each turned Horizontal or Vertical, «Aplicar recorte»; flip horizontal / vertical; rotate ±90°) and **Redimensionar** (width × height with the ratio locked by default, «Aplicar tamaño»). The sections are an accordion: one open at a time, Información first; the side column scrolls on its own so the stage never changes size. The preview canvas is drawn at device pixels (sharp on Retina). Every step goes on an undo/redo stack (the arrows in the header, «Descartar» drops them all); the stage shows the current size. «Aplicar recorte» / «Aplicar tamaño» only change the preview. The header keeps undo/redo in view and folds the rest — Copiar enlace, Abrir en una pestaña, Reemplazar, Eliminar — into an «Acciones» menu; any change (the name, the alt text or an image edit) swaps that menu for one **Descartar / Guardar** pair, as in Shopify: Guardar saves everything that changed (the image first, as a replace, then the name and alt text), Descartar drops it all. Guardar is a split button (`ui/split-button.tsx`): its chevron offers **Guardar como nueva imagen**: the edited image goes up as a new file in the same folder with the typed name (or «<nombre> (editada).<ext>» if it was not changed) and alt text, the original stays as it was, and the viewer moves to the new file. «Guardar» encodes the result (PNG and WebP stay what they were, anything else becomes a JPEG) and runs it through the same replace path as «Reemplazar» — same id, same name, every reference shows the edited image — then reloads it; the stored dimensions follow (the browser reads an image's pixel size and sends it on `POST /api/media/:id/complete`, since Cloudflare Images does not report it). Uploading a file whose name already exists asks first («Subir de todos modos» / «No subir»): the same file twice is billed twice. **Copiar enlace** (a row action, and in the viewer's header beside «Abrir en una pestaña») copies a public, permanent link under our own domain, `GET <api>/archivos/:id` (`apps/api/src/routes/files.ts`, outside the session gate): never a Cloudflare URL, never expiring, view only. An image is served as the file itself (the browser shows it on black, like a Shopify CDN link); a video gets a bare black page with Stream's player, the signed playback token minted fresh on every visit (so the page outlives the token's 24 h). Anyone with the link can see the file: it is meant for sharing a video or an image with someone outside the portal, not as the app's playback URL (the app still gets short-lived signed URLs).
- **Suscripciones** (`/suscripciones`) — see [billing.md](billing.md): set custom price/discount, comp, adjust next charge date, manual charge/retry, payment history, pause/cancel.
- **Reportes** (`/reportes`) — revenue over a period, by segment, MRR/churn (SQL over `subscriptions` + `payments`).
- **Panel** (`/`) — dashboard summary (currently redirects to `/ejercicios`).
