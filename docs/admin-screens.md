# Admin screens

The portal is a left **sidebar** + content area (`apps/admin/src/app/(app)/layout.tsx`). Nav lives in `apps/admin/src/components/sidebar.tsx`. Every screen is Spanish (copy from `src/i18n/es.ts`). Data goes through `@dmtx/api-client` + TanStack Query; forms use react-hook-form + Zod.

## Built

- **Login** (`/login`) — email/password via `@dmtx/auth/client`.
- **Ejercicios** (`/ejercicios`) — list with a status dropdown (Activos / Archivados / Todos) and a checkbox column. Selecting rows shows a bulk bar over the header: Agregar músculos, Agregar equipo (the same pickers as the form), Archivar / Restaurar, and "···" with Quitar músculos, Quitar equipo (tick which of the selection's tags to drop) and Eliminar (refused per exercise when a rutina, reusable block or user result uses it; the bar reports which stayed). `POST /api/exercises/bulk`. Create (`/nuevo`) and edit (`/[id]`) share `ExerciseForm` (name, description, multimedia, cues, aliases, difficulty, músculos, equipo). This is the **reference implementation** — copy its shape for the other entities.

## To build (roadmap order)

Each follows the same pattern: list (TanStack Table) + create/edit (RHF + Zod against `@dmtx/schemas`) + a resource on the API + a method on `@dmtx/api-client`.

- **Músculos** (`/musculos`) and **Equipos** (`/equipos`) — one flat list each, as a table: search, an add row at the top (Enter adds and keeps the focus for the next name), click a name to rename inline, and a checkbox column whose bulk bar (it covers the header row, like Shopify) deletes the selection after a confirm. Deleting a tag takes it off the exercises that carried it; the exercises stay. Each row shows how many exercises use it. The exercise form tags like Shopify's product tags: the field shows the chosen chips and an "⊕ Agregar" button opens a popover to search and tick existing ones; a name that doesn't exist is created from there ("Agregar «…»").
- **Rutinas** (`/rutinas`) — the big one. Type toggle (structured/video). For structured: a full-height **text editor** styled like VS Code (dark theme, tab bar, line numbers, gutter error markers, token colours, a "Problemas" panel underneath; `rutina-text-editor.tsx`) where the whole rutina is written in the [rutina text notation](rutina-text.md) — format on the first line, `N rondas:` groups, `41 burpees  kg tempo 0-3-1-1` items, `Calentamiento:`/`Enfriamiento:` sections — with autocomplete while typing (exercises by name/alias, typo-tolerant suggestions, units, modifiers; only an exactly written name resolves) and a "+" menu (gutter, or a click/Enter on a blank line) for structure: formats, rondas, descansos, plantillas, reusable blocks and other rutinas, inserted with ⟨placeholders⟩ that Tab walks through, inline diagnostics shown as a Grammarly-style card on hover or when the word is selected (suggestions apply on click; unknown exercise → "Crear ejercicio"), recognised exercise names read as links (dotted underline on hover) and a click opens the full exercise form in a dialog (the archived-exercise card has the same action; renaming rewrites the name in every section and version of the open rutina and keeps the old name as an alias), the athlete-facing preview always visible in the right column (it follows the active variant tab), and a searchable guide in a drawer behind the "Guía" button (`rutina-guide.tsx`): live examples (a real editor with a demo catalog, plus the athlete's preview) and CSS-animated scenes for the mouse-driven parts (the + menu, the error card, click-to-edit an exercise, the placeholders), so it never goes stale. A tab bar holds the **variants** (RX / Escalada / …): "+" copies the active tab into a new variant, double-click renames, ✕ removes; every tab is validated and saved with the base. Undo/redo buttons sit on the right (⌘Z / ⇧⌘Z, Ctrl+Z / Ctrl+Y). Select two or more lines → "Guardar como bloque" saves them as a reusable block; saved blocks and other rutinas are suggested by name and inserted whole. For video: a single media picker.
- **Bloques reutilizables** (`/bloques`) — reusable rutina text blocks (`reusable_blocks`): rename, edit text, delete. Created from the rutina editor.
- **Programas** (`/programas`) — a table (thumb, name, weeks, difficulty, status, updated) and the rutina editor in program mode: one bar above the editor holds a "Semana N" dropdown (switch week, duplicate one — the copy goes right after it — remove one, add an empty one) and the seven days of that week as cells (click to edit a day, drag to move it within the week; a dot = has content, hatched = rest day). The same bar says what the day is: structured text, a single video (like a rutina) or "Descanso". Catalog rutinas are reused through the + menu (their text is copied). Publishing refuses a day with nothing in it. Each day's rutina is saved as a workout owned by the program (not listed anywhere else).
- **Habilidades** (`/habilidades`) — the rutina editor in skill mode: the "Nivel ▾" dropdown lists the levels (add, rename, reorder with ↑↓, remove; the new one copies the active level), each level has the Rutina / Calentamiento / Enfriamiento tabs plus **Objetivo**: one exercise line per mark that unlocks the next level (`3 Dominadas`, `Plancha 60s`, `Sentadilla 5x5 @100 kg`); structure there is an error, so is a line without an amount, and in that tab the "+" menu offers exercises only. The preview ends with "Objetivo · para pasar al siguiente nivel". Publishing refuses a level without goals unless it is the last. Each level's rutina is saved as a workout owned by the skill (not listed anywhere else).
- **Colecciones** (`/colecciones`) — Netflix rows; add mixed items (workout/program/skill) with ordering.
- **Biblioteca** (`/biblioteca`) — the media library on Cloudflare Images (images) and Stream (videos). Uploads run in the background through a global queue (`lib/uploads.ts`, the tray bottom-right): the media record is created as `uploading` the moment the file is dropped and the field or tile gets its id right away, so the admin can save, change day or move around the portal while the bytes go straight to Cloudflare (`api.media.upload` with `onStarted`/`onProgress`: one multipart POST for an image, resumable tus chunks for a video). An image over 10 MB (Images' limit) is re-encoded as a JPEG in the browser first (`lib/prepare-image.ts`), same pixels, a tenth of the bytes. After the bytes are in, a video shows «Cloudflare está procesando el video…» until Stream has encoded it (a few minutes; the field, the thumbs and the list poll meanwhile) and then plays in the field through Stream's player; its duration comes from Stream. The tray lists the queue (scrolls when long) with «Cancelar» per file and «Cancelar todo»; the field has its own «Cancelar» while its file goes. Cancelling, also while Stream is still encoding, stops the transfer and deletes the record and the file at Cloudflare (`POST /api/media/:id/abort`), and the field lets go of the id. Reloading or closing the tab is the only thing that loses an upload (the browser asks first); a record left `uploading` with nothing in flight shows as interrupted and is removed by the admin. Failed uploads delete their record (references set null); a video Stream could not encode stays as `failed` until replaced. Clicking a tile opens the file at `/biblioteca/[id]`, the way Shopify opens a file: the image (or Stream's player) big on the left and, on the right, its name and alt text (editable, `PATCH /api/media/:id`), the details (type, dimensions, size, duration, date) and **Usado en** (`GET /api/media/:id/usage`: the exercises, rutinas, programs, skills, levels and collections that reference it, linked), plus Eliminar; the checkbox on a tile still marks it for bulk delete.
- **Suscripciones** (`/suscripciones`) — see [billing.md](billing.md): set custom price/discount, comp, adjust next charge date, manual charge/retry, payment history, pause/cancel.
- **Reportes** (`/reportes`) — revenue over a period, by segment, MRR/churn (SQL over `subscriptions` + `payments`).
- **Panel** (`/`) — dashboard summary (currently redirects to `/ejercicios`).
